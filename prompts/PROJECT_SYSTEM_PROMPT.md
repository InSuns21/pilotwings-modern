# Pilotwings Modern — ワークスペース・システムプロンプト

あなたは `pilotwings-modern` リポジトリで作業します。このプロジェクトは、親しみやすいミッション飛行ゲームに着想を得た、オリジナルのブラウザ向け3Dフライトゲームです。

## このファイルの役割

このファイルは**作業開始時の入口と正本への案内**だけを担当します。

飛行モデル、モジュール境界、カメラ、機体表示、安全判定などの設計ルールをここへ重複記載しないでください。  
ブランチ運用、検証、完了条件などの開発ルールもここへ重複記載しないでください。

## 正本

作業前に、変更内容に応じて以下を参照してください。

1. **設計・アーキテクチャの正本**  
   `docs/ARCHITECTURE.md`

   以下を管理します。
   - モジュールの責務境界
   - 飛行・失速・エネルギー・フレアのモデル
   - PITCH / PATH / 迎角の関係
   - 安全判定
   - 機体表示
   - カメラ
   - ワールド / ミッション
   - シミュレーション方式
   - 将来の拡張ポイント

2. **開発プロセスの正本**  
   `docs/DEVELOPMENT_RULES.md`

   以下を管理します。
   - `main` の健全性
   - 固定タイムステップや入力正規化などの実装上の基礎ルール
   - branch / PR の運用
   - テスト・ビルド・ドキュメント更新
   - 完了条件
   - GitHub Pages 互換性

3. **利用者向けの現在仕様**  
   `README.md`

   現在遊べる内容、操作方法、開発方法、公開URLなど、利用者が知るべき現行仕様を管理します。

## 作業時の原則

- アーキテクチャや複数ファイルにまたがる変更では、最初に `docs/ARCHITECTURE.md` と `docs/DEVELOPMENT_RULES.md` を確認する
- ユーザーの明示的な設計変更によって既存ルールが変わる場合は、該当する**正本だけ**を更新する
- 同じルールを複数のMarkdownへコピーしない
- 新しいルールを追加する前に、「設計ルール」か「開発ルール」か「利用者向け仕様」かを判断して置き場所を決める
- チャット履歴だけに重要な設計判断を残さない
- コード変更時は正本に従って必要なテストと検証を行う

## プロジェクトの不変条件

正本の詳細とは別に、次の前提だけはこの入口でも維持します。

- ブラウザで動作し、GitHub Pagesへ静的デプロイ可能なオリジナル作品であること
- タブレット / タッチ操作を第一級の対応対象とすること
- Nintendo のコード、ROMデータ、リッピング済みアセット、音楽、マップなどのプロプライエタリなゲーム内容を導入しないこと

設計詳細や数値しきい値はここへ追加せず、`docs/ARCHITECTURE.md` を更新してください。  
開発手順や完了条件はここへ追加せず、`docs/DEVELOPMENT_RULES.md` を更新してください。
